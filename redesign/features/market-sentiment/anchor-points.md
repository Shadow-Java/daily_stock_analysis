# anchor-points — 市场锚定点体系设计（价格锚 / 事件锚 / 个股锚）

> 版本: v0.1 | 日期: 2026-09-25 | 状态: 草稿待审核
> 演进自 dynamic-window 构想：动态窗口收编为"价格锚点"一种类型
> 关联: [storage-design.md](storage-design.md)、[api-call-chain.md](api-call-chain.md)、`../../platform/data-source/realtime-data-plan.md`

## 一、需求与定位

情绪页新增**锚定点栏目**：集中展示当前影响市场走势的所有锚定点。

三类锚点：

1. **价格锚**（原"动态窗口"）：指数从关键转折点累计涨跌了多少，大涨后首次冲高回落严重提醒、大跌后首次下杀回升提醒
2. **事件锚**：影响全球/大盘走势的关键事件（议息、关税、重大政策、宏观数据），事件未兑现/发酵中时市场围绕它定价
3. **个股锚**：短线市场的高度锚（空间板）与龙头锚（核心人气股），它们的断板/晋级牵动整个短线情绪

栏目回答一个问题：**"今天市场在盯着什么做交易？"**

## 二、统一语义：锚点生命周期

所有锚点共用一套状态语义，页面才有一致的展示与提醒逻辑：

| 状态 | 含义 |
|---|---|
| `active` | 生效中，市场解读框架围绕它 |
| `digested` | 已被消化/定价完毕（事件出尽） |
| `broken` | 被证伪/击穿（价格锚转折、空间板断板、事件落空） |
| `expired` | 自然到期（事件日已过且无后续发酵） |

每个锚点三要素：**锚定物**（是什么）、**存续期**（生效/失效时间）、**影响方向**（利多/利空/中性）。

## 三、三类锚点详设

### 3.1 价格锚（指数转折锚）

沿用原动态窗口状态机，作为价格锚的内部机制：

- **锚定物**：沪深300 的最近确认转折点（锚点价 + 锚点日）
- **窗口累计**：`cum = close / anchor_price - 1`；窗口极值 `window_high/low`
- **转折判定**（15:30 采集尾部，日线收盘价）：
  - 上涨段：`cum ≥ +5%` 且距窗口高点回撤 ≥ 3% → **冲高回落**（severe）→ 锚点迁移至窗口高点，转下跌段
  - 下跌段：`cum ≤ -5%` 且距窗口低点反弹 ≥ 3% → **下杀回升**（normal）→ 锚点迁移至窗口低点，转上涨段
- **防抖**：锚点确立后至少 3 个交易日内不触发；阈值默认即可运行，参数化待评审
- **冷启动**：近 250 个交易日日线回放状态机，避免冷启动丢失"大涨/大跌"前提
- 锚点迁移 = 原设计的"窗口重置"，转折信号即"锚点失效事件"

### 3.2 事件锚

- **锚定物**：单条事件（如"美联储议息 10-29""对华关税听证 11-XX"）
- **字段**：`event_date`（兑现日）、`title`、`scope`（`global` 全球大盘 / `cn_market` A 股 / `sector` 板块）、`expected_direction`（利多/利空/中性）、`status`、`note`、`source`（来源链接）
- **状态流转**：`pending`（待兑现，事件日之前）→ `active`（发酵中）→ `digested / broken / expired`；MVP 人工流转，倒计时自动计算
- **来源**：MVP 人工录入；后续新闻 LLM 自动提取候选 → 人工确认（见 §六.4）
- **与价格锚联动**：事件兑现日附近的转折，可标注"疑似事件驱动"（R3，先不做自动归因）
- **展示**：按 scope 分组，pending 事件显示倒计时；global 类事件联动外盘行情展示"事件后美股反应"辅助判断是否已消化

### 3.3 个股锚（短线高度锚 + 龙头锚）

- **高度锚**：当前最高连板股（空间板）。来自已有 `market_pool_detail_snapshot`（limit_up 池，`consecutive_boards` 最大）
- **龙头锚**：连板 ≥ 3 中成交额最大的个股（MVP 简化规则）；后续结合热点板块生命周期标注所属主线
- **信号**（15:30 池明细落库后，与昨日对比推导）：
  - **空间板断板**（昨日最高板今日未涨停）→ 高度锚失效提醒（**severe**，与短线退潮共振，常领先温度转弱）
  - 空间板晋级成功 → 高度打开，锚点上移（info）
  - 龙头股大跌（≤ -5% 或跌停）→ 赚钱效应受损（normal）
- **不重复计分**：双温度短线公式已含"空间板"项；个股锚只做**叙事化展示 + 事件提醒**，复用池数据推导，不新增计算口径
- **不落库**：MVP 由池明细实时推导（含对比昨日），无独立表；历史归档需求出现时再加表（§六.2）

## 四、UI：锚定点栏目

情绪演化区上方新增**锚定点卡片**，三个区块：

```
┌ 锚定点 ────────────────────────────────────────┐
│ 价格锚  06-18 低点起  累计 +8.2%   [上涨段]      │
│ 事件锚  🌐美联储议息 10-29（待兑现·8天） 利空     │
│         🇨🇳十四五花 03-05（发酵中） 利多          │
│ 个股锚  高度: XX股份 7板   龙头: YY科技 5板      │
│ ⚠ 当日提醒横幅（severe 红色 / normal 蓝色）      │
└───────────────────────────────────────────────┘
```

- 每行：类型图标 + 锚定物 + 生效日/倒计时 + 状态标签 + 方向色（A 股习惯：利多红/利空绿）
- 当日锚点事件（价格转折/断板）显示横幅，severe 红色置顶
- 锚点行 hover 显示详情（窗口高低点、事件 note、龙头所属板块）

| 表 | 用途 | 关键字段 |
|---|---|---|
| `market_price_anchor_state` | 价格锚状态（每指数一行，upsert） | index_code UNIQUE, direction, anchor_date/price, window_high_date/price, window_low_date/price, cum_chg_pct, retrace_pct, rebound_pct, updated_trade_date |

## 六、优化建议（待审核取舍）

1. **锚点数量克制**：每类 active 上限（事件锚 ≤ 5、个股锚 ≤ 2）——锚点太多等于没有锚点；超出按影响度排序，弱锚自动降权归档
2. **失效要显式了结**：`broken/digested` 必须记录时间与关键价（事件锚记"事件后指数实际反应"），沉淀**锚点史**；回看"当时市场锚定什么"对复盘价值极高
3. **锚点快照进预期管理**（Phase 2 联动）：录入大盘预期时自动带上当前锚点列表，复盘时对照"锚点是否兑现"辅助评分——把锚点体系变成预期管理的输入件而非孤立展示
4. **事件锚自动候选工作流**：新闻/日历 LLM 提取候选（标题、日期、scope、方向 + 来源），人工一键确认；纯人工维护必然荒废
5. **提醒分级路由**：severe（价格转折/空间板断板）→ 通知推送；normal → 页面横幅；避免全部进推送造成疲劳
6. **个股锚结合主线**：龙头锚标注所属热点板块，主线整体退潮时龙头锚的可信度单独降级（"逆主线孤龙"与"主线龙"含义不同）
7. **回放校准**：价格锚阈值用历史段回放（2024-09 快涨 / 2025-04 深跌）；个股锚对照典型退潮段验证"断板信号是否领先于温度转弱"
8. **全球事件锚联动外盘**：global 事件展示事件后美股/亚太实际走势，用数据验证"已消化/未消化"，而非纯人工拍状态

## 七、API

- 新端点 `GET /market-sentiment/anchors`（读库 only）：`{price: {状态+窗口}, events: [...], stocks: {height_board, leader}, today_events: [...]}`
- 事件锚管理：`POST /market-sentiment/anchors/events`、`PATCH .../events/{id}`（录入与状态流转，MVP 单用户不做权限）
- 历史事件流水：`GET /market-sentiment/anchors/events/history?days=N`（可选，R2）

## 九、开放问题

1. **事件锚录入入口**：Web 管理页 vs 先用 API/脚本顶着？
2. **龙头锚判定**：成交额最大（现方案）vs 封单额最大 vs 涨速/人气？（MVP 用成交额，待回看校准）
3. **价格锚载体**：沪深300（与趋势温度同源，建议）vs 上证指数（"大盘"直觉）
4. **个股锚历史**：推导式无历史，锚点史若要含"历史高度锚是谁"，需在池明细落库基础上补推导回填（池明细已按日落库，可回填，无需新表）
