# AI 操作建议（operation-advisor）设计文档

> 版本: v0.1 | 日期: 2026-09-25 | 状态: 草稿（待评审，未开工）
> 需求：根据目前的行情，AI 推荐当前持仓比例、能否买入、是否要卖出；给出买入可能性最高的前 3-5 个板块、3-5 个个股；给出当前适合的打法（低吸/追高/打板/观望），并按打法分组候选个股、每日动态打分观察。
> 前置：`../market-sentiment/`（数据采集与情绪页）、`../strategy-recommendation/design.md`（兄弟功能）、`../trading-growth/decision-signal.md`（打分想法来源）。

---

## 一、一句话核心思路

**规则引擎先算分（免费、可解释、每日跑）→ LLM 只做一次定性研判（结合事件/新闻给理由和风险提示）→ 输出「市场周期 → 今日打法 → 仓位建议 → 板块 TopN → 个股 TopN（按打法分组 + 打分轨迹）→ 持仓股买卖提示」。**

不做「AI 拍脑袋荐股」：每个结论都能展开因子明细（为什么分高/低），打分每日刷新并保留轨迹，让用户看到"观察池怎么演化"。

## 二、与现有功能域的边界（不重复造轮子）

| 现有能力 | 复用方式 |
|---|---|
| `market_sentiment` 采集（涨停池/炸板/跌停/涨跌家数/成交额/板块涨幅/梯队 ladder/情绪分/聚焦事件） | **全部复用**，本功能零新增采集（阶段 1）；直接消费同一批快照表 |
| `focus`（明日重点/周聚焦/月聚焦事件） | 作为 LLM 研判与题材催化因子输入 |
| `decision_signals` 决策信号链路（单股分析 → 信号落库） | 持仓股买卖提示直接复用该链路，不新建平行实现 |
| `strategy-recommendation`（用户自定义策略实时推荐） | 边界互补（见下）；阶段 3 共享候选池/扫描层 |
| `anchor-points`（空间板/龙头断板/事件锚） | 打板与龙头因子的语义来源 |

**与 strategy-recommendation 的区别**：那是「用户自定义策略 → 实时批量扫描 → 推荐引擎」；本功能是「系统内置的每日操作参谋」——回答的是**该不该做、用什么打法、仓位多少、手里这些怎么办**，输出是一份「每日操作建议」而不是实时榜单。两者共享数据与（未来的）扫描层，但服务、表、页面独立。

## 三、难点坦白（这个需求确实难，先划清能做/难做/不做）

| 类别 | 内容 | 说明 |
|---|---|---|
| ✅ 能做（现有数据即可算） | 连板梯队与龙头地位、炸板率、涨跌家数、板块涨幅、情绪分 | 全部来自 market_sentiment 快照，盘后即可算 |
| ✅ 能做（盘后数据 join） | 赚钱效应（昨日涨停股今日高开率/溢价率）、低吸股回调天数与回撤幅度 | 池明细（昨日）+ 当日行情对比，新增一个计算任务，无需新数据源 |
| ⚠️ 难做（需要新采集） | 竞价强度因子（9:25 竞价数据）、分时均价线 | 盘中采集，放阶段 3；初版用收盘近似因子替代 |
| ⚠️ 难做（需要样本积累） | 打法历史命中率、打分权重校准 | 先硬编码规则 + 可调权重，回测是阶段 3 |
| ❌ 明确不做 | 实盘对接、自动交易、收益承诺 | 所有输出标注「仅供参考，非投资建议」；建议只是决策辅助 |

## 四、输出物定义（页面 6 个区块）

```
┌─────────────────────────────────────────────────────────┐
│ ① 市场周期判断：情绪阶段（冰点/回暖/主升/高潮/退潮）        │
│    + 今日结论一句话（LLM 研判摘要）                        │
├─────────────────────────────────────────────────────────┤
│ ② 仓位建议：建议仓位区间（如 20%-40%）+ 理由（3 条因子）    │
│    + 动作提示（可加仓 / 维持 / 建议减仓 / 建议空仓观望）    │
├─────────────────────────────────────────────────────────┤
│ ③ 今日打法：低吸 / 追高 / 打板 / 观望（主打法 + 次打法）    │
│    + 该打法适用条件说明                                   │
├─────────────────────────────────────────────────────────┤
│ ④ 板块 TopN（3-5 个）：买入可能性打分 + 龙头 + 催化事件     │
├─────────────────────────────────────────────────────────┤
│ ⑤ 个股 TopN（3-5 个/打法）：按打法分组（低吸组/追高组/打板组）│
│    每条：打分 + 轨迹（近 5 日）+ 性价比 + 明日预期 + 竞价预案  │
│    （次日 9:25 对照预案执行：企稳低吸 / 破位放弃或止损）        │
├─────────────────────────────────────────────────────────┤
│ ⑥ 持仓提示：持仓股逐只「持有/加仓/减仓/清仓/观察」+ 理由    │
└─────────────────────────────────────────────────────────┘
```

生成时机：**每日收盘采集完成后（15:30 与 market_sentiment 同批次）生成一次**；阶段 3 增加盘中动态刷新。

## 五、核心设计 1：市场周期判断与打法路由

### 5.1 情绪阶段量化

现有 `overview` 已有情绪分（由涨停家数/涨跌家数/涨停占比等合成）。阶段 2 将其档位化为五阶段，并叠加赚钱效应因子：

| 阶段 | 判定（初版规则，权重可调） | 对应打法路由 |
|---|---|---|
| 冰点 | 情绪分低 + 跌停多 + 炸板率高 + 连板高度≤2 | 观望 / 只做超跌低吸 |
| 回暖 | 情绪分回升 + 昨日涨停今日溢价转正 + 首板增多 | **低吸** 为主，试错打板 |
| 主升 | 涨停家数高位 + 赚钱效应强 + 空间板打开 | **追高/打板** 为主，低吸次之 |
| 高潮 | 涨停家数峰值 + 大面积涨停 + 分歧转一致 | 降仓兑现，只留龙头 |
| 退潮 | 炸板率升 + 龙头断板 + 亏钱效应（昨日涨停今日均溢价为负） | **观望**，只留低吸防守 |

### 5.2 打法路由输出

每日产出：`primary_style`（主打法）+ `secondary_style`（次打法）+ 每个打法的「适用条件」文案。个股候选按打法分组（见 §6）。

## 六、核心设计 2：打分体系（难点核心）

> 本节为概览；**因子公式、权重、阶段阈值、观察池进出池规则的实现规格见 [scoring-and-evolution.md](scoring-and-evolution.md)**，两处冲突时以该文档为准。

### 6.1 三套独立评分模型（因子不同，互不复用）

**低吸分**（龙头回调低吸，来源 decision-signal 笔记）。**硬门槛：只做龙头股**（连板≥2 且为板块最高板/曾带动板块涨停潮），非龙头不入低吸池：

| 因子 | 方向 | 说明 |
|---|---|---|
| 龙头地位 | + | 曾连板高度 / 板块内 rank |
| 回调天数 | + | 涨停后回调 1-3 天，**每多 1 天加分**（用户明确要求），>4 天衰减 |
| 回撤幅度 | − | 回调未破位（未破 10 日线/未吞没启动阳线）加分，破位重扣 |
| 量能萎缩企稳 | + | 回调缩量 + 当日企稳信号 |
| 板块仍活跃 | + | 所属板块仍在涨幅榜 / 有同板块新涨停 |
| 情绪一致性 | ± | 回暖/主升期加分；退潮期低吸也降权 |

**追高分**（强势股接力）：

| 因子 | 方向 | 说明 |
|---|---|---|
| 当日强度 | + | 涨幅、量比、换手 |
| 板块梯队 | + | 同板块涨停家数 / 梯队完整性（龙头-中军-跟风） |
| 赚钱效应 | + | 昨日涨停股今日高开率（阶段 1 用溢价率近似） |
| 阶段约束 | ± | **仅主升/回暖可追**；退潮期追高分整体打折 |
| 风险惩罚 | − | 高位放量滞涨、当日炸板史 |

**打板分**（题材/龙头板）：

| 因子 | 方向 | 说明 |
|---|---|---|
| 梯队位置 | + | 连板高度是否为市场空间板 / 板块龙头 |
| 题材催化 | + | 聚焦事件（focus）中是否有相关催化、题材持续性 |
| 封板质量 | + | 封单/成交比，历史炸板率（阶段 1 用炸板池近似） |
| 阶段约束 | ± | 冰点/退潮期打板分整体打折；回暖期只允许龙头首板试错 |

### 6.2 每日动态打分与轨迹（用户核心诉求）

- **每日 15:30 对观察池全体候选重算分数**，写 `advisor_stock_score`（含因子明细 JSON）；
- 每条记录带 `prev_score`/`delta`，前端展示**近 5 日打分轨迹**（迷你柱/折线）；
- 观察池动态：连续 3 日降分或破位 → 移出观察池；升分 → 升榜标注（↑ 新上榜）；
- **性价比** = (目标价 − 现价) / (现价 − 止损价)，按打法给出参考触发条件：
  - 低吸：「回调至 ¥X（10 日线/0.5 回撤位）缩量企稳可低吸，破 ¥Y 止损」；
  - 追高：「放量过 ¥Z 可追，回落至均价线下止损」；
  - 打板：「若竞价强度达 N（阶段 3），排板参与」。

### 6.3 板块打分

个股分按板块聚合（板块温度 = Σ 个股分 × 权重）+ 板块自身因子（今日涨幅榜 rank、涨停家数、梯队完整度、催化事件数）→ 板块 TopN（3-5）。

### 6.4 明日预期与竞价预案

每晚为池内每只股生成「明日预期 + 竞价预案」四情景表（强高开 / 平开 / 小幅低开 / 破位 → 各自动作），次日 9:25 集合竞价对照执行——开盘前看一眼竞价结果即知买不买，无需盘中犹豫。实现规格见 [scoring-and-evolution.md §3.8](scoring-and-evolution.md)。

## 七、核心设计 3：仓位建议与持仓提示

### 7.1 仓位建议（规则给出区间，LLM 补充理由）

```
建议仓位区间 f(情绪阶段, 赚钱效应, 用户风险偏好)
  冰点/退潮: 0%-20%   回暖: 30%-50%   主升: 50%-80%   高潮: 30%-50%（兑现）
  再按用户 max_position_pct 与风险等级收缩
动作提示 = 对比「建议区间中值」与「用户当前实际仓位」→ 加仓/维持/减仓/空仓观望
```

用户当前实际仓位来自持仓录入（§8 `user_position`），未录入时只给区间不给动作。

### 7.2 持仓股买卖提示（复用 decision_signals 链路）

每日对持仓股跑既有单股分析（SkillRouter → StrategyEngine → `decision_signals`），叠加情绪阶段生成提示：

| 持仓情况 | 提示 |
|---|---|
| 信号 buy + 主升期 + 仓位未满 | 加仓（给出参考加仓位） |
| 信号 hold / 中性 | 持有（附止损位） |
| 信号 sell / 持仓板块进入退潮 / 高潮兑现期 | 减仓 / 清仓 |
| 触发止损价 | 止损提示（置顶） |

## 八、数据模型（SQLite，新增 6 表）

| 表 | 用途 | 关键字段 |
|---|---|---|
| `advisor_daily_report` | 每日建议快照 | trade_date(unique), status(draft/final), emotion_score, market_phase, primary_style, secondary_style, position_low, position_high, action_hint, llm_summary, factor_json, created_at |
| `advisor_stock_score` | 个股×打法×日期打分 | trade_date, code, name, style, score, rank, factor_json, close, entry_ref, stop_loss, target, cost_performance, conclusion(可买/观察/放弃), prev_score, delta, in_pool, next_expect, auction_plan_json |
| `advisor_sector_score` | 板块×日期打分 | trade_date, sector_code, sector_name, score, rank, factor_json, leaders_json, catalysts_json |
| `user_profile` | 用户画像（单用户） | capital, risk_level(conservative/balanced/aggressive), max_position_pct |
| `user_position` | 持仓录入 | code, name, cost_price, volume, opened_at, status(open/closed), closed_pnl |
| `advisor_position_hint` | 持仓股每日提示 | trade_date, code, action(hold/add/reduce/exit/watch), reason, source(decision_signal/advisor), signal_id |

`decision_signals` 不动结构；`advisor_position_hint.signal_id` 关联既有信号。

## 九、LLM 层设计（成本控制关键）

- **不是逐股调 LLM**。流程：规则引擎全量打分（免费）→ 取各打法 Top N + 持仓股 → **一次 LLM 调用**生成整份研判：
  - 输入：情绪快照摘要 + 各打法 Top N 候选（含因子明细）+ 近期聚焦事件 + 持仓信号；
  - 输出（结构化 JSON）：市场周期结论、今日打法确认（可否决规则路由）、每条推荐的 1-2 句理由 + 风险提示、仓位区间微调；
  - LLM 只能调整顺序/否决/补充理由，**不能发明规则外的新标的**（白名单约束，防幻觉）。
- 复用现有 LLM 配置与客户端（`src/services` 既有 LLM 调用链），不新增接入。
- LLM 失败降级：直接输出规则引擎结果 + 模板文案，status=draft。

## 十二、分阶段落地（每阶段独立可用）

| 阶段 | 内容 | 说明 |
|---|---|---|
| 阶段 1（MVP） | 盘后规则引擎打分 + 生成每日建议（①-⑤ 全区块，纯规则分 + 模板文案）+ 页面只读展示 | 零新增采集，全部复用 market_sentiment 快照；赚钱效应因子用池明细 join 算 |
| 阶段 2 | LLM 研判接入 + 情绪阶段五档化 + 持仓录入/仓位动作提示 + 持仓股 decision_signals 提示 + 打分轨迹页 | 需要用户录入持仓后 ⑥ 才有意义 |
| 阶段 3 | 盘中动态刷新（竞价强度因子，需新采集）+ 打法历史命中率回测 + 打分权重校准 + 与 strategy-recommendation 共享候选池/扫描层 | 观测验证后再决定是否上 |

## 十三、风险与边界

- **合规**：所有输出标注「AI 生成，仅供参考，不构成投资建议」；不提供收益预测数字，只给触发条件与止损参考；
- **正确性风险**：打分权重初版为经验硬编码，未经回测——页面需展示因子明细让用户自行判断，避免"黑箱信任"；
- **数据风险**：market_sentiment 采集降级时（degraded），advisor 需标「数据不完整」并降低置信度输出，不静默；
- **过拟合风险**：回测样本少（每日一个快照），命中率统计需长期积累，阶段 3 才展示，避免误导。

**回滚方式**：独立表 + 独立服务 + 独立页面，`git revert` 对应提交即可；不触碰 market_sentiment 与 decision_signals 既有契约。
