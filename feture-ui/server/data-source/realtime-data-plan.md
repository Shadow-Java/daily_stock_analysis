# 实时数据获取方案

> 生成日期：2026-09-22
> 目标：让 feture-ui 大盘情绪页所需的各数据项，以「可接受的实时程度」获取。
> 前置：见同目录 `data-source-audit.md`（数据源现状）与 `../storage-audit.md`（存储现状）。
类似项目：https://github.com/Doubixilin/moyu-kanpan
> 同花顺金融数据API：https://fuyao.aicubes.cn/docs/api-reference/prices/
---

## 一、实时性分级（回顾）

| 档位 | 源 | 实时程度 | 主要瓶颈 |
|---|---|---|---|
| 准实时 | AkShare / efinance（底层东财/新浪） | 秒级，但代码限流 2~5s | 免费源反爬、`_enforce_rate_limit` |
| 真实时 | pytdx（通达信协议）、tencent | 亚秒级快照/分时 | 数据面窄（无聚合数据） |
| 延迟 | yfinance（美股/韩股）、tushare、baostock | 15min ~ 收盘后 | 上游本身延迟 |

结论：**大盘情绪页的聚合类数据（涨停池/涨跌家数/板块）只能走东财/新浪，最快秒级且需留限流余量；真正的亚秒级只对「分时/快照」有意义。**

## 二、分数据项的实时获取方案

| 数据项 | 实时目标 | 数据源 / 接口 | 轮询策略 | 降级 / 备注 |
|---|---|---|---|---|
| 涨停池（含首封时间/连板/炸板次数/所属行业/封单） | 盘中 30~60s | AkShare `stock_zt_pool_em` | 分钟级轮询 | 东财盘中实时，已实现 `get_limit_up_pool` |
| 炸板池 | 盘中 30~60s | AkShare `stock_zt_pool_zbgc_em` | 分钟级轮询 | **需新增接口** |
| 跌停池 | 盘中 30~60s | AkShare `stock_zt_pool_dtgc_em` | 分钟级轮询 | **需新增接口** |
| 昨日涨停表现 | 盘前一次 + 盘中 30~60s | AkShare `stock_zt_pool_previous_em` | 开盘前加载 + 盘中跟随 | **需新增接口** |
| 涨跌家数 / 成交额（量能） | 盘中 1~2min | AkShare `stock_zh_a_spot_em`（全市场快照） | 分钟级，较重需节流 | 已实现 `get_market_stats`，全量下载 ~秒级 |
| 首封时间 / 连板 / 板块 | 随涨停池 | 涨停池内字段 | 同上 | 直接分桶/聚合，无需额外请求 |
| 龙头 / 小弟识别 | 随涨停池 | 规则计算（连板+封板时间+炸板+行业） | 每次涨停池刷新后重算 | 纯本地计算，无网络 |
| 主力净流入（个股/板块） | 盘中 1~2min | AkShare 资金流接口（东财） | 分钟级 | 已实现 `fundamental_adapter`，大盘聚合需补 |
| 两融余额 | **日级（T+1）** | AkShare `stock_margin_sse` / `stock_margin_szse` | 每日盘后一次 | **需新增接口**，非实时 |
| 新高 / 新低 | 收盘后计算 | 日线历史 OHLCV 本地计算 | 每日收盘快照 | 从 `stock_daily` 算 60 日新高，无网络 |
| 焦点个股（成交额/换手率） | 盘中 1~2min | 全市场快照排序 | 分钟级 | 复用 `get_market_stats` 的 spot 数据 |
| 焦点个股（龙虎榜） | **盘后** | AkShare `stock_lhb_*_em` | 收盘后一次 | 已实现 `get_dragon_tiger_context` |
| 热点事件 / 新闻 | 5min | `search_service` / 资讯源 | 5 分钟 | 已有 `src/search_service.py` |
| 美股（道指/纳指/标普/SOX/金龙/VIX） | 隔夜定格 | yfinance `get_main_indices(region='us')` | 早盘一次性加载 | **SOX/金龙需加映射**；盘中补纳指期货（延迟） |
| 韩股（KOSPI/KOSDAQ/三星/海力士） | 盘中 15~20min | yfinance `get_main_indices(region='kr')` + 个股 | 8:00-15:30 低频轮询 | yfinance 延迟，接受；三星/海力士需加个股代码 |

## 三、推荐实时架构（免费源下的最优解）

```
┌────────────────────────────────────────────────────────┐
│                    大盘情绪页 (feture-ui)                │
└───────────────────────────┬────────────────────────────┘
                            │ REST/JSON API (Pydantic)
┌───────────────────────────▼────────────────────────────┐
│                   数据服务层 (feture-ui/server)           │
│  · 轮询调度器（分钟级 tick，多源并行）                      │
│  · 短 TTL 缓存 + 负缓存 + 熔断降级                         │
│  · 计算层：龙头/小弟识别 · 量能轨迹 · 双维度温度 · 外盘温度   │
└───────┬───────────────────────────┬────────────────────┘
        │ 分钟级轮询                  │ 收盘快照
┌───────▼──────────────┐   ┌────────▼──────────────────────┐
│ 实时层 DataFetcherManager│   │ 快照层（新增）                 │
│ · AkShare 东财/新浪       │   │ · 15:30 每日 JSON/SQLite 存档 │
│ · pytdx 分时快照(可选)     │   │ · 情绪时间序列（近 N 日轨迹）   │
│ · yfinance 外盘指数       │   │ · 两融/龙虎榜/新高新低 盘后落库 │
└──────────────────────────┘   └─────────────────────────────┘
```

要点：
1. **分钟级 tick 是免费源的安全档**：东财限流 2~5s，聚合多接口 + 熔断后，30~60s 一轮最稳。
2. **盘后快照层**负责「近 N 日轨迹」：量能/双维度温度/涨停高度/外盘温度等时序，收盘后存档累积。
3. **计算型指标**（龙头识别/新高新低/量能放缩）走本地计算，不额外发请求。
4. **外盘天然延迟**：美股隔夜定格 + 韩股延迟轮询即可，不要追求 tick 级。

## 四、分阶段落地

| 阶段 | 内容 | 实时程度 |
|---|---|---|
| 阶段 1（MVP） | 东财/AkShare 分钟级轮询 + 15:30 收盘快照 | 盘中分钟级 |
| 阶段 2 | 接入 pytdx 补盘中分时/快照，情绪页加「盘中实时快照」 | 分时亚秒级 + 聚合分钟级 |
| 阶段 3 | 付费源（tushare 积分 / 同花顺 iFinD / 券商 Level-2） | 亚秒级聚合 |

## 五、需要新增/补齐的代码

1. **数据接口**（`data_provider/akshare_fetcher.py`）：
   - 炸板池 `stock_zt_pool_zbgc_em`、跌停池 `stock_zt_pool_dtgc_em`、昨日涨停 `stock_zt_pool_previous_em`
   - 两融 `stock_margin_sse` / `stock_margin_szse`
   - 美股 SOX（^SOX）、纳斯达克中国金龙 → 补进 `us_index_mapping.py`
   - 韩股三星（005930.KS）、SK海力士（000660.KS）个股代码
2. **快照存储层**（`feture-ui/server` 或 `src/`）：
   - 15:30 每日情绪快照（JSON 或 SQLite 加表）
   - 累积成情绪时间序列，支撑「近 N 日轨迹」
3. **数据 API 骨架**（`feture-ui/server`）：
   - 直接调 `DataFetcherManager`，返回 Pydantic 结构化 JSON（不经过 agent 工具文本链路）
4. **轮询调度器**：分钟级 tick + 多源并行 + 熔断 + 短 TTL 缓存

## 六、一句话总结

免费源下，**聚合数据走「东财/AkShare 分钟级轮询」，盘后走「15:30 快照累积时间序列」，外盘接受天然延迟**；只有分时/快照才值得上 pytdx/付费源追求亚秒级。
